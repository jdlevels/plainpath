Please refine the design with the following requirements:

1. Replace real-brand mock/demo content.
The current sample uses a spoofed Microsoft invoice. Do not use real company names in demo/mock content.

Use fictional names instead, such as:

- Atlas Vendor Services

The tool can still demonstrate fake-invoice or suspicious-document behavior, but use fictional company names only.

2. Avoid overclaiming fraud or authenticity.
Document Trust Check should not say a document is definitely real or definitely fake unless that is explicitly proven.

Use careful wording:
- possible trust concern
- risk indicator
- suspicious signal
- requires human verification
- confirm with the original source
- not a legal or forensic determination

Avoid:
- “This is fake”
- “This is fraud”
- “This proves the document is forged”
- “Verified authentic”

3. Add a trust score explanation.
If the design shows a score such as 22/100, add a small explanation near the score:

“Trust score reflects document consistency, source clarity, metadata signals, and risk indicators. It is not a legal or forensic determination.”

Keep this compact.

4. Refine the Completed Trust Overview panel.

Right panel order should be:

A. Trust Summary
- 4–6 lines maximum
- clear but cautious
- explain whether the document appears low-risk, needs review, or has major trust concerns

B. Trust Score / Confidence Strip
- Trust score
- Confidence level
- document type confidence
- critical red flags
- needs human review

C. Major Trust Concerns
Show only top 3–5 by default.
Each concern card should include:
- short title
- one-line explanation
- severity chip
- source chip
- recommended action

D. Verification Checklist
Make this action-oriented:
- confirm sender through a known phone/email
- verify payment destination independently
- compare invoice/order/reference numbers
- request original source file
- confirm signatures or official identifiers
- do not act/pay until verified if high-risk signals exist

E. Document Consistency
Keep compact.
Check:
- names
- dates
- addresses
- amounts
- signatures
- referenced attachments
- formatting consistency

F. Metadata / Structure Signals
Keep compact.
Include:
- file type
- page count
- creation/modification clues if available
- scan quality
- OCR confidence
- missing metadata
- unusual structure

G. Source Traceability
Keep visible and clickable, but compact.
