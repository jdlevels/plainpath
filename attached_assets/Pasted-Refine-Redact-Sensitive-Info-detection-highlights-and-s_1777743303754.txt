Refine Redact Sensitive Info detection highlights and selection behavior.

Problem:
The Redact tool now supports page navigation, but the detected highlights are too broad. Yellow highlights appear across whole lines, sentence regions, section headers, legal references, and paragraphs. This makes it look like the entire line will be redacted, even when only a specific name, account number, case number, email, phone number, or other sensitive value should be removed.

This is a trust issue. Redaction must be precise, user-controlled, and visually clear.

Do not redesign the entire tool.
Do not weaken PDF redaction safety.
Do not remove the rasterized/image-only export requirement.
Do not change pricing, billing, Stripe, auth, marketing, public demos, database schema, or unrelated tools.
Do not reintroduce e-signature, Digital Signature, Dropbox Sign, or send-for-signature.

Required behavior:
1. Change the redaction preview from broad line/paragraph highlighting to exact-value highlighting.
2. Candidate highlights should wrap only the exact detected text span where possible:
   - person name
   - email
   - phone
   - address
   - SSN
   - bank/account/routing number
   - date of birth
   - case/reference number only when truly sensitive
   - other direct identifiers
3. Do not highlight entire lines by default.
4. Do not highlight section headings, legal citations, evidence code citations, table headers, or ordinary legal analysis as redactable PII.
5. Legal citations such as “Evid. Code § 780(c),” “Pen. Code § 995,” section numbers, table titles, and legal headings should be treated as non-sensitive by default.
6. Names should be candidate-only, not automatically selected, unless the current product setting intentionally auto-selects names. If auto-select remains, make it very clear that the user can deselect names.
7. Add clear visual state rules:
   - yellow/amber = candidate found, not yet selected
   - red/rose = selected for redaction
   - black = applied redaction in redacted preview/export
8. Update copy from:
   “13 values permanently removed”
   to a safer pre-export phrase such as:
   “13 selected values prepared for redaction”
   or:
   “13 selected values will be removed from the redacted copy”
9. Only use “permanently removed” after the safe redacted export is generated and confirmed.
10. The right-side list must show exact detected values, not broad line fragments.
11. Each candidate row should support:
   - select/deselect
   - jump to page
   - show match count
   - category
   - confidence/severity
12. Clicking a highlighted value in the PDF preview should toggle that exact value or open its candidate row.
13. Add a user-controlled scope option for each candidate:
   - redact this instance only
   - redact this exact value everywhere
   - redact full line
   - redact custom area
14. Default scope should be:
   - “this exact value everywhere” for clear identifiers like SSN, email, account number
   - “this instance only” or “candidate only” for names and legal/case references
15. Redaction boxes in the final PDF must match the exact selected values or user-selected custom areas.
16. If exact coordinates are uncertain, show the candidate in the list but do not auto-select it. Use wording:
   “Needs review — exact position uncertain.”
17. The user must always control what gets removed.
18. Preserve page navigation across all pages.
19. Preserve selected redactions when moving between pages.
20. Preserve safe rasterized/image-only redacted PDF export.
21. Preserve original PDF unchanged.

Specific false-positive examples to prevent:
1. Do not mark “Evid. Code § 780(c)” as sensitive by default.
2. Do not mark “Pen. Code § 995” as sensitive by default.
3. Do not mark full section headings like “4A.6 Cross-Examination Module” as sensitive by default.
4. Do not mark entire legal-analysis paragraphs as sensitive by default.
5. Do not highlight a whole row when only a name or account/reference number inside the row is the candidate.

UI copy updates:
- Candidate banner:
  “PlainPath found possible sensitive values. Review and choose what to redact.”
- Selection banner:
  “Selected values will be removed from the redacted copy.”
- Applied/export-ready banner:
  “Redacted copy ready. Selected values were removed from the exported PDF.”
- Page warning:
  “Review every page before sharing.”

4. Confirm legal citations are not auto-selected as sensitive PII.

7. Confirm user can jump from a candidate row to the correct page.
8. Confirm selecting one exact value does not accidentally redact the surrounding sentence.
9. Confirm “redact full line” only happens if the user explicitly chooses that scope.
10. Confirm final redacted PDF black bars align only over selected exact values/custom areas.
11. Confirm exported redacted PDF cannot reveal redacted values by search, select, or copy.
12. Confirm original PDF remains unchanged.
13. Confirm TypeScript baseline does not increase.
14. Confirm app and API server start cleanly.
