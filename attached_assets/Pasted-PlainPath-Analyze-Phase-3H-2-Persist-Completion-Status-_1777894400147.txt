1. Storage key

Persist completionStatus using a stable per-analysis key.

Preferred key:

plainpath_completion_${analysis.id}

If analysis.id is unavailable, use a safe fallback based on available stable document fields, but do not store document text.

Acceptable fallback shape:
plainpath_completion_fallback_${safeHash(documentTitle + documentType)}

Do not store:
- raw document text
- source quotes
- document body content
- user uploaded file data
- personal document content

Store only:

Record<string, boolean>

Where key = completionObject.id and value = true/false.

2. Load behavior

When feature flag is ON and an analysis loads:

- compute completionObjects as already done
- read localStorage for the analysis key
- merge stored completionStatus into current completionStatus
- only keep keys that still exist in current completionObjects
- ignore stale IDs
- default missing IDs to false
- if localStorage is unavailable, fail silently and continue with empty state

Important:
Stored values should win for known IDs.
New completion objects should start false.

3. Save behavior

Whenever the user toggles an item done/not-done in Plan, Complete, or drawer:

- update React state immediately
- persist the updated Record<string, boolean> to localStorage
- write only the cleaned object containing current known completionObject IDs
- do not write unrelated state

Use either:
- immediate localStorage.setItem on toggle, or
- debounced 250–300ms write

Keep it simple and reliable.

4. Reset behavior

Add a small “Reset progress” action in Complete mode and/or Packet mode only.

Recommended placement:
- Complete mode header/action area
- Packet mode header/action area

Behavior:
- clears completionStatus for the current analysis
- removes the localStorage key for that analysis
- returns all items to not done
- does not delete the analysis
- does not delete the uploaded document
- does not affect other analyses

Copy:
“Reset progress”

Confirmation:
Use a native confirm() or existing confirm pattern if available:

“Reset checked progress for this document? This will not delete the analysis or uploaded document.”

If user confirms:
- reset completionStatus to {}
- remove localStorage key
- progress bar returns to 0%

If user cancels:
- no change

When localStorage is unavailable:

Do not make this alarming.
Do not show a blocking error.

When switching to a different analysis.id:

- load that document’s own saved progress
- do not carry previous document’s checks into the new one

- stale localStorage from old object IDs should be ignored
