==================================================
T001 — PRE-RUN INTAKE AND CONFIRMATION POLISH
==================================================

Goal:
Before the user clicks generate, the builder should feel clear, intentional, and ready.

Required:
- ensure there is a true pre-run state before generation
- make the primary action obvious
- make selected builder options / template / document type clearly visible
- if source inputs or builder selections can be removed/changed before generation, make that clear
- reduce ambiguity about what will be generated
- if title/name is relevant before generation, make it clearer or easier to understand

Focus on:
- confidence before clicking Generate
- visible readiness state
- less clutter or ambiguity in the intake area
- clear primary CTA placement

Do not redesign the entire form.
Polish the existing workflow.

==================================================
T002 — GENERATION / GATING / ERROR-STATE POLISH
==================================================

Goal:
Generation should fail gracefully, gate clearly, and never feel broken.

Required:
- preserve the fixed upgrade modal behavior
- ensure gating states are user-readable and intentional
- loading/generating state should feel distinct from idle
- error states should be clear and non-confusing
- if generation is blocked, user should understand why and what next action exists
- avoid runtime-overlay-style failures and ambiguous silent failures

Also:
- if progress text/loading copy is weak or generic, improve it
- if button disabling/loading states can be tightened, do so
- if retry behavior exists or can be safely improved, do so carefully

Do not add new billing systems or gate logic.
Polish the existing behavior.

==================================================
T003 — POST-GENERATION OUTPUT WORKFLOW CLARITY
==================================================

Goal:
Once the draft is generated, the user should immediately understand what they can do next.

Required:
- make next actions clear in the result workspace
- ensure action hierarchy is sensible:
  - primary next step(s)
  - secondary actions
  - utility actions
- avoid a cluttered or equally-weighted action bar if everything currently competes
- make it easier to understand what each action does:
  - download/export final file
  - sign
  - analyze
  - redact
  - export JSON / utility outputs
- if some actions should be grouped or visually de-emphasized, do that
- preserve the improved split-screen output workspace

Also:
- if output metadata (title, generated time, saved state, template type, etc.) helps clarity, surface it lightly
- make sure the result does not feel like a dead-end after generation

==================================================
T004 — SAVE / EXPORT / SESSION IDENTITY CONSISTENCY
==================================================

Goal:
The generated document/session should feel like a real, understandable object.

Required:
- make session/document identity clear
- if title is weak, improve how it is surfaced
- if rename is easy and safe to add, do so only if the underlying architecture already supports it or the change is truly small
- clarify save vs download/export semantics
- if current save behavior is invisible or confusing, improve it
- preserve any existing autosave/manual save patterns where relevant
- if the output is already persisted, make that understandable without clutter

Do not add a whole new session management system here.
Keep this focused and low-risk.
