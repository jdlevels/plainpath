==================================================
T001 — PDF INTAKE CLASSIFICATION FOUNDATION
==================================================

Goal:
When a user opens a PDF, PlainPath should understand what kind of PDF it is and route them appropriately.

Required:
- classify PDFs as one of:
  - text PDF
  - scanned/image PDF
  - mixed PDF
- make this classification visible enough for the user to understand what happens next
- preserve current PDF Editor open flow for normal text PDFs
- if scanned/image PDF is detected, offer the OCR workflow instead of pretending direct text editing is available
- if mixed PDF is detected, handle it gracefully and explain that some pages may need OCR

The intake should feel like:
- Open PDF
- detect file type
- continue into the correct editing/utility workflow

Do not overcomplicate the first UI.
Keep the decision clear and stable.

==================================================
T002 — OCR / SCANNED-PDF FOUNDATION
==================================================

Goal:
Scanned PDFs should become searchable and editable through an OCR-backed workflow.

Required:
- add OCR foundation for scanned/image PDFs
- extract text from scanned pages
- create a searchable text layer
- preserve original page image underneath
- store OCR results in a session-safe structure
- expose confidence or “review recommended” signals only if cleanly available
- allow the user to review/correct OCR text in a practical workflow

At minimum for this pass:
- scanned PDF opens
- OCR runs
- extracted text becomes searchable
- OCR text can be reviewed/edited in session
- export path preserves the corrected result directionally

Important:
This does NOT need to be perfect “desktop PDF editor parity” in one pass.
But it must be a real foundation, not a fake placeholder.

Also:
- OCR should be integrated into the PDF platform flow, not treated as a random separate tool card
- AI may be used only where it meaningfully assists OCR review, not as a vague add-on

==================================================
T003 — SESSION SAVE / EXPORT / SAVE AS FOUNDATION
==================================================

Goal:
Users must be able to work on a PDF and finish with a real output path.

Required:
- preserve the distinction between:
  - Save session / work-in-progress
  - Download final PDF / Save As output
- allow the user to rename the output file before download if current architecture supports it cleanly
- ensure session save persists editor state / OCR corrections / page operation state where applicable
- ensure final export produces a real PDF output, not only a markup shell
- keep save/export wording clear and consistent

Important product rule:
PlainPath must move toward exporting a real edited PDF, not just annotations floating above the original.

If browser limitations prevent direct “save anywhere” semantics:
- implement the correct browser-safe version:
  - Save session in app
  - Download / Save As final PDF to user-selected location via browser
