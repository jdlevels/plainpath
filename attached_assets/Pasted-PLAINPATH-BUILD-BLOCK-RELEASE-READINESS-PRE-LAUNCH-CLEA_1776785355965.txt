==================================================
T001 — ROUTE / TOOL ACCESS / STATE CONSISTENCY AUDIT
==================================================

Goal:
The app should feel coherent and predictable as users move between core tools.

Required:
- inspect route naming, page titles, breadcrumbs, and back-navigation affordances
- normalize obvious inconsistencies where low-risk
- ensure authenticated tool entry states feel intentional
- ensure lock/gate states use product language, not developer language
- ensure session/detail pages feel like part of one product family

Examples:
- “Compare Versions” vs route/page title wording
- “PDF Editor” vs “Open in PDF Editor” continuity
- “Redact Info” vs “Redact before sharing” wording consistency
- builder result labels and action text consistency
- tool card to workspace naming continuity

Do not rename core products arbitrarily.
Only fix obvious inconsistency or confusing wording.

==================================================
T002 — ERROR / EMPTY / LOADING / NO-DATA UX CLEANUP
==================================================

Goal:
No major flow should feel broken when there is simply no data, no result, or a blocked state.

Required:
- improve weak empty states in core tools
- improve weak loading states that still feel too generic
- improve low-quality error messages where safe
- ensure “0 results / 0 differences / no uploaded document / no sessions” states feel intentional
- ensure locked/gated states explain what the user can do next
- ensure pages do not look dead or unfinished when they are empty

Focus on real user clarity, not visual decoration.

Examples of acceptable cleanup:
- better no-session / no-document copy
- more intentional “no differences found” or “no issues available” state
- small CTA/support text improvements
- cleaner loading labels
- better empty-state spacing/structure

==================================================
T003 — CROSS-TOOL ACTION WORDING AND USER GUIDANCE CLEANUP
==================================================

Goal:
Primary actions across core document tools should feel understandable and consistent.

Required:
- audit action labels like:
  - Save
  - Download PDF
  - Export
  - Analyze
  - Review
  - Check
  - Redact
  - Continue with
  - Open in PDF Editor
- tighten any ambiguous or inconsistent wording
- ensure save vs export vs download remains distinct
- ensure the user understands the next step after major tool actions
- add lightweight guidance where a user could otherwise be confused

Examples:
- “Analyze” vs “Analyze this contract”
- “Redact Info” vs “Redact before sharing”
- “Export JSON” placement and wording
- “Saved just now” / “last saved” / “download final file” distinctions
- guidance around no auto-save / local-save / persistent-save where relevant

Do not add tutorial overlays or big walkthrough systems here.
Keep it lightweight.
