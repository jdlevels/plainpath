Known limitation from Phase 2A:
visibleTabs uses activeMode, but activeMode defaults to "understand" on initial render. If a user deep-links directly to a Plan tab such as `?tab=deadlines`, the tab can load correctly, but the active mode may still display Understand until the user interacts.

Required fix:
Make activeMode derive correctly from the active tab on:
1. initial page load
2. URL tab param changes
3. StatPill clicks
4. StartHereBanner CTA clicks
5. manual tab clicks
6. manual mode clicks

Rules:
- If active tab is Plain English, Source Sections, Overview, or Key Terms, activeMode should be "understand".
- If active tab is Checklist, Required Docs, Deadlines, Risks & Notes, Action Pack, or What's Missing, activeMode should be "plan".
- Complete and Compile modes should remain explicit mode selections only for now.
- If the current tab does not belong to the selected mode, choose the first valid tab for that mode.
- Do not let mode and tab state drift out of sync.
