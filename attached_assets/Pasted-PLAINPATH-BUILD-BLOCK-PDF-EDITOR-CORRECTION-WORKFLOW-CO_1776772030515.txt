T001 — HANDOFF-LOADED ISSUE WORKFLOW POLISH
==================================================

Goal:
When PDF Editor is opened from Compare Versions, the correction workflow should be immediately understandable.

Required:
- preserve current fromCompare / handoff flow
- make preloaded issue zones clearly visible
- make issue count obvious
- provide a clean issue list in the right panel
- selecting an issue in the panel should clearly focus/navigate to the matching marked zone/page in the document
- current issue / selected issue should be visually obvious
- show enough issue metadata to make correction practical

Each issue row should include, where available:
- severity
- page number
- short label/title/category
- optional AI explanation/category if already available in session data
- source indicator that it came from Compare Versions when applicable
- corrected/open/pending status if such state exists or can be added cleanly

Do not overload the UI with too much text.
Favor fast scanability and clear mapping from issue row → document zone.

If needed, add a compact "Issues" panel mode specifically for handoff-loaded sessions.

==================================================
T002 — SAVE / AUTOSAVE / UNSAVED-STATE SYSTEM
==================================================

Goal:
PDF Editor must feel safe and professional during correction work.

Required:
- visible Save button in toolbar
- Save control visually highlights when there are unsaved changes
- timed autosave approximately every 60 seconds
- clear saved/saving/unsaved indicator
- avoid noisy UX; keep it clean
- unsaved changes should be based on real editor state, not guesswork
- save should not interrupt editing flow

Implementation expectations:
- manual Save remains primary visible action
- autosave should be secondary support, not the only mechanism
- if save fails, surface a clear non-blocking error state
- if autosave succeeds, show subtle confirmation
- avoid excessive save calls; debounce/coalesce appropriately
- do not break current persistence model

If there is already save behavior, tighten it instead of replacing it blindly.
