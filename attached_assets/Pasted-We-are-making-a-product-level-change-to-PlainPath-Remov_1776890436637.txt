PART 2 — ADD THE NEW TOOL
==================================================

Create a new first-class tool:

Clause Extractor & Obligation Tracker

This tool must be visibly distinct from:
- Analyze a Document
- Document Trust Check
- Build a Contract
- Contract Review / Fair Deal Check
- Compare Versions

Its purpose is:
Extract structured clause data and obligations from contracts/agreements and turn them into actionable fields.

==================================================
PART 3 — V1 TOOL SPEC
==================================================

INPUT
- accept PDF and Word documents
- support drag/drop + click upload
- support single-document upload for V1
- hold at a pre-run confirmation state after upload with a primary action button:
  “Extract Clauses” or “Analyze Clauses”
- allow remove/X on uploaded file before processing

OUTPUT SECTIONS
Build a structured results workspace with these sections:

1. Key Dates
- effective date
- execution date if found
- expiration date
- renewal date
- notice deadline / notice period

2. Parties
- party names
- roles if identifiable (client/vendor, landlord/tenant, employer/employee, etc.)
- signer names if present

3. Financial Terms
- payment amount
- payment schedule
- late fees if found
- refund language if found

4. Legal Clauses
- governing law
- termination clause
- auto-renewal
- liability cap
- indemnity
- confidentiality / NDA
- assignment / transfer
- dispute resolution / arbitration

5. Obligations
- clear bullet list of who must do what
- obligations should be attributed to the relevant party when possible

6. Missing / Not Found
- clearly show important fields not detected
- do not hallucinate; if not found, say not found

RESULT BEHAVIOR
- every extracted item should include:
  a. label
  b. extracted value
  c. confidence or source snippet if feasible
  d. source section reference/snippet if available
- show plain-English meaning where useful, but keep this tool more structured/data-first than Analyze a Document
- allow copy/export of results

EXPORT
For V1, support:
- Copy all results
- Export CSV
- optionally export structured JSON if easy
- do not block V1 on PDF report export if that slows delivery

==================================================
PART 4 — UI / UX REQUIREMENTS
==================================================

This should feel like a major product surface, not a small utility.

1. LAYOUT
- use a document-first workspace
- if split-screen helps, left = uploaded document preview, right = extracted structured results
- if split-screen is not useful for this tool, use a strong single-workspace layout with document preview toggle
- prioritize readability and actionable structured output

2. DESIGN
- match PlainPath’s existing high-quality app styling
- clean cards/sections
- strong hierarchy
- easy scanning for dates, financial terms, and obligations
- visual emphasis on deadlines and renewal-related risk
- missing items should be clearly shown, not buried

3. INTERACTION PATTERNS
- visible Save button if results can be saved
- timed autosave only if already standard
- uploaded document removable before processing
- progress/loading state should reference the actual uploaded document, not a generic placeholder
