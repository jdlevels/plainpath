Apple privacy label principle:
The privacy label must account for data collected by the app and third-party partners integrated into the app.

PlainPath launch tools:
1. Analyze a Document
2. Contract Review

Known likely data categories to evaluate:
- Contact Info: email address
- User ID: Clerk user ID / RevenueCat user ID / subscription identifier
- Purchases: subscription status / entitlement information
- User Content: uploaded documents, document text, generated analysis results
- Diagnostics: crash logs, performance data, logs if collected
- Usage Data: app interactions / product analytics if collected
- Identifiers: device ID or app instance ID if collected by SDKs
- Financial Info: only if Apple/StoreKit handles it directly; do not mark as collected by PlainPath unless app code receives payment card details

For each possible data type, produce a table with:
1. Data type
2. Is it collected? Yes / No / Owner confirmation required
3. Source in app/code/policy
4. Purpose:
   - App Functionality
   - Account Management
   - Payment / Subscription Access
   - Analytics
   - Diagnostics
   - Other
5. Linked to user? Yes / No / Owner confirmation required
6. Used for tracking? Expected No unless confirmed otherwise
7. Retained? Yes / temporary / not retained / owner confirmation required
8. Notes

Specific questions to answer:

1. Account data
Confirm whether Clerk collects:
- email
- user ID
- authentication/session data

2. Subscription data
Confirm whether RevenueCat / StoreKit collects or processes:
- subscription status
- purchase entitlement
- app user ID

3. Uploaded documents
Confirm whether uploaded documents/document text are:
- processed to return results
- retained after processing
- stored in user history
- deleted after processing
- sent to AI provider
- used for training

Do not overstate. If history stores analysis text but not original files, state that precisely.

4. AI provider processing
Confirm:
- provider identity if visible in code/env/docs
- whether submitted content is used for training
- whether data is retained
- whether business/API no-training terms are in place

Mark owner confirmation required if not fully verifiable from repo/policy.

5. Analytics / diagnostics
Search for analytics, crash reporting, telemetry, Sentry, PostHog, Google Analytics, Firebase, LogRocket, or similar SDKs.
If none exist, mark analytics/diagnostics as not found in code.
If present, identify exactly what may be collected.

6. Tracking
Search for ad SDKs, cross-app tracking, ATT-related code, advertising identifiers, or third-party tracking SDKs.
Expected:
No tracking.
Confirm by code search.

7. Privacy policy alignment
Compare the recommended privacy label selections against the actual Privacy Policy.
Flag mismatches.
