Current issue:
The current Analyze a Document screen is visually clean, but it still behaves too much like a summary/risk review screen. It shows summary, risks, next steps, and dates, but it does not strongly deliver the original core value:

“Tell the user exactly what needs to be completed, what is missing, and what to do next.”

Goal:
Refine Analyze a Document so the right panel becomes a stronger document action plan.

Keep the existing left document viewer and right panel layout.

Update the Completed Analyze Overview right panel order to:

A. Plain-English Summary
B. Action Plan Snapshot
C. Step-by-Step Required Actions
D. Missing Items / Information Needed
E. Deadlines & Time-Sensitive Items
F. Key Risks / Watchouts
G. Source Traceability

Specific requirements:

1. Add Action Plan Snapshot near the top.

This should be a compact card or chip row showing:
- total actions found
- urgent actions
- missing items
- deadlines found
- source-backed findings
- overall status: Ready / Needs completion / Needs review

Example:
5 actions found · 2 urgent · 3 missing items · 1 deadline · Needs completion

2. Make Step-by-Step Required Actions the strongest section.

Each action card should include:
- Step number
- short action title
- plain-English instruction
- why it matters
- priority: urgent / important / optional
- status: not started / in progress / complete
- responsible party if known
- deadline if known
- source chip

Example card:

Step 1 — Confirm payment deadline  
Instruction: Verify when payment is due and whether late fees apply.  
Why it matters: The document includes payment timing and penalty language.  
Priority: Urgent  
Status: Not started  
Responsible party: User / Client / Vendor if known  
Due: June 30, 2026 if known  
Source: p.2 §5.1

3. Add Missing Items / Information Needed.

This section should identify anything the user likely needs before acting.

Examples:
- missing signature
- missing date
- missing attachment
- missing reference number
- missing payment amount
- missing contact information
- unclear responsible party
- unclear renewal terms
- missing supporting document

Each missing item card should include:
- item title
- why it matters
- how to resolve it
- source chip if available

Use cautious wording:
- appears missing
- may need verification
- not found in the provided document
- confirm before acting

4. Strengthen Deadlines & Time-Sensitive Items.

Each deadline card should include:
- date or timeframe
- what it applies to
- consequence if stated
- priority
- source chip

5. Keep Key Risks / Watchouts secondary.

Analyze a Document should still show risks, but this tool should not feel like Contract Review or Trust Check.

The main identity should be:
- understand the document
- know what must be completed
- know what is missing
- know what to do next

6. Source chip behavior must apply to action steps.

When a source chip is clicked:
- scroll the left document viewer to the relevant section
- highlight the source section
- show the evidence banner
- keep the related action card active

7. Add visual completion-state direction.

In canvas, show action statuses:
- Not started
- In progress
- Complete

This can be UI-only for now if persistence is not implemented yet.

8. Mobile Analysis view should prioritize action.

Mobile order:
- Plain-English Summary
- Action Plan Snapshot
- Step-by-Step Required Actions
- Missing Items
- Deadlines
- Key Risks
- Source chips

Document tab remains second.

9. Preserve safe wording.

Avoid:
- guaranteed outcome
- legal advice
- must sign
- must pay
- legally required unless the document clearly states it

Use:
- based on the document
- appears to require
- verify before acting
- source-backed next step
- consider professional review if high-risk

Canvas states to show:
- Completed Analyze Overview with stronger Action Plan
- Source chip active / action step highlighted
- Low Confidence state with partial action plan
- Mobile Analysis view
- Mobile Document view
