PlainPath Funnel + Access Control Audit — Try for Free, Demo Cards, Login, Dashboard, Paid Access

Goal:
Run a comprehensive audit and fix pass for PlainPath’s public funnel, demo access, login flow, dashboard access, and paid-user gating.

This is launch-critical.

Current rule:
Visitors should NOT access the full dashboard of tools.
“Try it free” should open a separated demo/try-free experience, not the authenticated dashboard.
Demo cards should open their own demo pages or demo modal/sandbox.
Only registered paid users, Admin users, or approved reviewer/admin test accounts should access the real dashboard and full tool routes.

Current active tools:
1. Analyze a Document
2. Document Trust Check
3. Build a Contract
4. Contract Review
5. Redact Sensitive Info
6. Ask This Document
7. Clause Extractor
8. Compare Versions
9. Document Builder

Do not:
- Add new tools
- Change pricing
- Change Stripe checkout behavior on web
- Add StoreKit
- Add Google Play Billing
- Reintroduce e-signature
- Add Dropbox Sign
- Change database schema unless a blocker requires it and is reported first
- Create migrations unless explicitly approved
- Break the admin reviewer account
- Break web Stripe checkout

====================================================
A. Define the Correct Access Model
====================================================

Implement and verify this access model:

1. Public visitor / not authenticated
Allowed:
- Marketing homepage
- Pricing
- Support
- Privacy
- Terms
- How it works
- Demo landing page
- Individual demo pages/cards
- Sign in
- Sign up

Not allowed:
- /app
- /dashboard
- /documents
- /my-analyses
- full real tool pages
- saved work
- real AI processing behind paid routes unless intentionally demo-limited

Expected behavior:
- If visitor clicks “Open App,” send to sign-in or sign-up.
- If visitor clicks “Try it free,” send to a public demo/try-free route, not the dashboard.
- If visitor clicks a demo card, open a demo page/sandbox for that tool.

2. Authenticated but unpaid user
Allowed:
- Account/billing/subscription page
- Upgrade prompt
- Possibly limited free trial/demo route if intentionally implemented

Not allowed:
- Full dashboard with all real tools
- Full tool execution
- Saved document library access beyond allowed account area
- Pro-only tools

Expected behavior:
- If unpaid user tries /app or /dashboard, show upgrade gate or redirect to /subscribe.
- Do not show the full operational dashboard as if they are paid.
- Do not expose full tool routes unless access is allowed.

3. Paid Pro user
Allowed:
- Dashboard
- All paid tools according to plan
- My Documents
- My Analyses
- Save/export where supported

4. Admin / reviewer account
Allowed:
- Full dashboard
- All 9 tools
- No payment prompt
- No Stripe required
- Works from incognito/fresh session
