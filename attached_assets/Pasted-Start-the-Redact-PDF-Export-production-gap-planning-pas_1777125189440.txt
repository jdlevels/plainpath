Goal:
Plan the correct production implementation for true redacted PDF export.

Current known gap:
Redact Sensitive Info currently exports .txt even when the input was a PDF. For production, PDF uploads must export a real redacted PDF copy with black redaction blocks embedded into the PDF layout.

Important:
This is not just visual preview. The exported PDF must actually remove or permanently cover the sensitive information so it cannot be copied, searched, selected, or recovered from the exported file.

Planning requirements:

1. Inspect current Redact implementation.
Review:
- Redact.tsx
- PII detection API
- current export function
- uploaded file handling
- text extraction flow
- whether original PDF bytes are preserved
- whether coordinates/page positions are available
- current redaction item data structure

2. Determine the current data gap.

Answer:
- Do we currently have original PDF file bytes available at export time?
- Do we currently have page coordinates for detected sensitive items?
- Are redaction items character-index based only?
- Can current detection results map back to PDF coordinates?
- Is the current paper preview coordinate-accurate or only text-position simulated?

3. Recommend safest implementation path.

Evaluate options:

Option A — pdf-lib overlay redaction
- load original PDF
- draw black rectangles over detected coordinates
- export new PDF
- limitation: text may remain underneath unless page content is flattened/rasterized or content is actually removed

Option B — rasterize pages then draw redaction bars
- render each PDF page to image
- draw black bars over redaction areas
- create a new PDF from the redacted page images
- stronger privacy because underlying text is not recoverable
- larger file size
- best for production privacy if exact text removal is difficult

Option C — server-side PDF redaction service/library
- use a PDF processing library or service that can truly remove/redact content
- stronger but may add dependency/cost

4. Recommended production standard.

PlainPath should prefer privacy over perfect text preservation.

Recommended direction:
- if true content-level PDF redaction is not reliable, use rasterized-page export for redacted PDFs
- exported redacted PDF should not contain selectable original sensitive text
- black bars should be embedded into the final page image/PDF
- original document remains unchanged
