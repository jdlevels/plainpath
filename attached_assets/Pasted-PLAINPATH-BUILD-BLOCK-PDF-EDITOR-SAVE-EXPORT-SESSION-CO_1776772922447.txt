==================================================

Goal:

Required:
- tighten reopen reliability for saved sessions
- ensure persisted ops, corrected state, and issue state restore cleanly
- make session title/identity clearer if current UI is weak

T002 — EXPORT / FINAL OUTPUT WORKFLOW CLARITY
==================================================

Goal:
When a user finishes correction work, the save/export flow should be obvious and trustworthy.

Required:
- clarify the difference between:
  - saving the session/work-in-progress
  - exporting/downloading the corrected PDF output
- ensure export uses the correct/latest saved editor state
- export action should have clear labeling and status feedback
- if the current export button/flow is ambiguous, fix the wording and toolbar grouping
- if export is disabled until a valid state exists, make that obvious
- avoid user confusion between “Save” and “Download/Export”

Implementation expectations:
- preserve existing export capability if already working
- if current export reads in-memory state and that is acceptable/safe, document it
- if export should first flush pending changes, implement that safely
- if exporting should preserve corrected highlights/annotations/edits exactly as visible, ensure that is true
- provide subtle but clear success/failure feedback

Do not redesign all export architecture.
Polish and harden the current flow.
