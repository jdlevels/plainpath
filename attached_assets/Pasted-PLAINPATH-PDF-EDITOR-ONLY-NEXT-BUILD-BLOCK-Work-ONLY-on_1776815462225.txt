T001 — TRUE TEXT EDIT MODE INSIDE PDF EDITOR SESSION
Implement a first practical version of editable text inside /pdf-editor/:id.

Requirements:
- Add a distinct “Edit Text” mode/tool in PdfEditorSession.
- It must work for:
  a) searchable/text PDFs
  b) scanned PDFs after OCR exists
- User can click a detected text region/block/line and edit its text in the right pane.
- Store these edits as real session ops, not temporary UI-only state.
- Exported PDF must reflect the edited text.

Implementation guidance:
- Reuse the existing OCR/session model where possible.
- For text PDFs, inspect existing text extraction paths and derive editable text regions.
- For scanned PDFs, use OCR data as the editable text source after OCR is run.
- If exact native glyph replacement is not feasible with current stack, use the acceptable fallback:
  - cover original region
  - render replacement text into the same bounding area
  - preserve readable page output
- Support at minimum:
  - replace selected text block
  - multiline text edit where block supports it
  - font size adjustment or auto-fit within bounding box
- Do not over-engineer full word processor behavior in this pass.

Acceptance:
- Edit text in a text/searchable PDF → save → reload → edit persists
- Download corrected PDF → edited text appears in exported file
- Edit OCR text in scanned PDF → save → reload → export reflects the change
