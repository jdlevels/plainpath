PlainPath Public Demo System Audit — Built-In Live Example for Each of 9 Tools

Goal:
Before changing the Try for Free / login / dashboard gating flow, audit and complete the public demo system so every active PlainPath tool has its own built-in demo example.

This pass is about demo readiness only.

Current active tools:
1. Analyze a Document
2. Document Trust Check
3. Build a Contract
4. Contract Review
5. Redact Sensitive Info
6. Ask This Document
7. Clause Extractor
8. Compare Versions
9. Document Builder

Core requirement:
Each tool must have a public demo experience that lets a visitor see what the tool does before purchasing.

The demo must:
- Open from the marketing/demo page.
- Use built-in sample/demo data.
- Show a realistic live example or realistic static simulation.
- Clearly label itself as Demo / Sample Preview.
- Not require payment.
- Not expose the real dashboard.
- Not show My Documents or My Analyses.
- Not save user data.
- Not use real user documents.
- Not route into paid app tools unless the user intentionally signs in.
- Not reintroduce e-signature.
- Not mention Digital Signature, Dropbox Sign, Send for Signature, or e-signature.
- Not show stale “8 tools” or “6 tools” copy.

Do not:
- Change Stripe.
- Change auth architecture.
- Change database schema.
- Create migrations.
- Add new tools.
- Change pricing.
- Add StoreKit.
- Add Google Play Billing.
- Reintroduce e-signature.
- Add Dropbox Sign.
- Break the admin/reviewer account.
- Connect public demos to private user data.

====================================================
C. Demo Content Requirements by Tool
====================================================

Verify or create one built-in demo example for each tool.

1. Analyze a Document
Demo document:
- Small business permit, lease notice, IRS-style letter, medical bill, or simple agreement.
Demo must show:
- Uploaded/sample document preview
- Plain-English summary
- action plan
- deadlines
- missing items
- risks
- source-backed sections

2. Document Trust Check
Demo document:
- Suspicious collection letter, fake invoice, fictional credit agreement, or questionable notice.
Demo must show:
- Trust/risk score
- suspicious indicators
- consistency signals
- what to verify
- safe next steps
- cautious wording, no absolute “fake/authentic” claims

3. Build a Contract
Demo flow:
- Built-in guided question example for a freelance/service/lease/NDA-style contract.
Demo must show:
- guided questions
- generated contract preview
- editable/preview result if available
- static signature/date line allowed only as document layout field

4. Contract Review
Demo document:
- Credit card agreement, service agreement, lease, or employment-style agreement.
Demo must show:
- score/summary
- red flags
- watch-outs
- missing protections
- negotiation suggestions
- legal-safe disclaimer

5. Redact Sensitive Info
Demo document:
- Sample document containing fake name, account number, phone, email, address, or case number.
Demo must show:
- detected sensitive items
- selected redactions
- black-bar preview
- original unchanged message
- redacted PDF/download message if supported

6. Ask This Document
Demo document:
- Lease, contract, policy, or notice.
Demo must show:
- document preview
- built-in suggested questions
- at least 2–3 sample Q&A responses
- answer tied to source/document section

7. Clause Extractor
Demo document:
- Service agreement, lease, vendor contract, or NDA.
Demo must show:
- extracted clauses
- parties
- dates
- obligations
- missing/not identified clauses
- source-backed findings
- no fake source highlight for missing clauses

8. Compare Versions
Demo documents:
- Original lease/agreement and revised version.
Demo must show:
- side-by-side original and revised preview
- additions
- deletions
- modified terms
- risk/meaning shifts
- change list/right panel
- no crash

9. Document Builder
Demo document:
- SOP, employee onboarding manual, policy, checklist, or internal manual.
Demo must show:
- template selection or prebuilt sample document
- left live document preview
- clickable/editable block concept if available
- AI Guide panel
- Outline/Edit/Style/Export tabs
- .txt export if supported
- PDF/DOCX clearly marked coming soon if not implemented

D. Demo Page Structure Standard
====================================================

Each individual demo page should follow the same structure:

Header:
- Tool name
- Demo / Sample Preview badge
- One-line explanation
- CTA: “Use this with your own document”

Main body:
- Left side: sample document or output preview
- Right side: demo result/intelligence/action panel

Footer/CTA:
- “Create account to use with your own documents”
- “Open PlainPath”
- Optional: “Back to all demos”

Do not show:
- My Documents
- My Analyses
- Billing
- Full dashboard
- Saved real sessions
- user account data
- payment prompt inside demo
- e-signature references
