Implementation requirements:

1. Use the approved modified PlainPath Scan Workspace Standard.
Desktop layout:
- Original document panel
- Revised document panel
- Change Intelligence panel or drawer
- Original and Revised panels must remain readable
- Both document panels should support independent scrolling where feasible
- Change Intelligence should also scroll independently

2. Preserve all approved states:
- Empty State
- Processing State
- Completed Compare Overview
- Change chip active / before-after highlighted state
- Low Confidence State
- Error State
- Mobile Summary View
- Mobile Original View
- Mobile Revised View

3. Completed Compare Overview panel order:
A. Change Summary
B. Change / Confidence Strip
C. Key Changes
D. Added Language
E. Removed Language
F. Modified Terms
G. Possible Risk Changes
H. Source / Change Traceability

Possible Risk Changes should remain secondary, not dominant.

4. Keep Compare Versions focused on comparison.
Primary purpose:
- compare two document versions
- identify added language
- identify removed language
- identify modified terms
- identify unclear or moved language
- show before/after evidence
- help the user decide what needs review

Do not turn this into a contract-risk dashboard.

5. Use comparison-focused wording.
Use:
- changed language
- added language
- removed language
- modified term
- term to verify
- possible risk change
- not legal advice

Avoid:
- legal conclusion language
- you should sign / you should not sign
- legally invalid
- guaranteed protection
- replaces an attorney

6. Color semantics must remain clear:
- green = added language
- red = removed language
- amber = modified / unclear / needs review
- purple = active source/change traceability
- blue = neutral action/help
- gray = unchanged context

Important:
Red does not automatically mean “bad.” In Compare Versions, red can simply mean removed language.

7. Change chips must be functional.
When clicked:
- active change chip becomes visually selected
- original document scrolls to old/removed/modified section
- revised document scrolls to new/added/modified section
- both matching sections highlight when both exist
- evidence banner shows Before and After text
- related change card remains active

If only one side has text:
- added language highlights only in Revised
- removed language highlights only in Original

8. Added Language section:
Each item should show:
- added term or clause
- where it appears
- plain-English meaning
- source chip
- action only if needed

9. Removed Language section:
Each item should show:
- removed term or clause
- where it used to appear
- plain-English meaning
- source chip
- why the user may want to verify it

Avoid saying a removal is automatically bad.

10. Modified Terms section:
Each item should show:
- before language
- after language
- what changed
- source chip
- term to verify, if needed

11. Low-confidence message must use:
“PlainPath could compare part of these documents, but scan quality limits comparison confidence.”

12. Error state message must use:
“Version comparison could not be completed.”

Actions:
- Try again
- Upload different files
- Ask This Document
- Analyze a Document

- Summary

- Revised
