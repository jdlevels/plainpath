We need to restructure the PII redaction feature into a first-class standalone PlainPath tool.

Strategic decision:
Redaction should NOT only live as a hidden pre-step inside other tools.
It should become its own core tool, just like:
- Analyze a Document
- Document Trust Check
- Contract Review
- Build a Contract

New tool name:
Redact Sensitive Info

==================================================
PRODUCT GOAL
==================================================

Users should be able to:
1. open the Redact Sensitive Info tool directly
2. upload / paste / scan a document
3. detect likely sensitive information
4. choose exactly what to redact
5. apply selected redactions
6. copy / save / export the redacted version
7. send the redacted version into another PlainPath tool if they want

This tool must also remain cross-connected with the other tools.

==================================================
NEW PRODUCT STRUCTURE
==================================================

Add a 5th core tool:
- Redact Sensitive Info

This tool should appear:
- on homepage with the other tool cards
- in nav/tool menus
- anywhere else the core tools are listed

==================================================
REQUIRED USER FLOWS
==================================================

Primary redaction flow:
- user opens Redact Sensitive Info
- uploads/pastes/scans document
- PlainPath detects likely PII
- user selects what to redact
- user clicks Apply selected redactions
- PlainPath creates redacted version
- user can:
  - Copy redacted text
  - Download/export redacted copy
  - Save redacted copy
  - Send to Analyze
  - Send to Trust Check
  - Send to Contract Review

Cross-tool flow:
If user is already inside:
- Analyze
- Trust Check
- Contract Review

They should still see a shortcut like:
- Redact first
- Open in Redact
- Use redacted version

But the main redaction logic/workspace should now live in the standalone Redact tool.
