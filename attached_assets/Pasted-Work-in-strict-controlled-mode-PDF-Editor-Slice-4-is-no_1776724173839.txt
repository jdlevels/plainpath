CURRENT TASK
Create the full architecture blueprint for PlainPath Compare Versions as a first-class standalone tool.

PRODUCT POSITION
Compare Versions is a manager/supervisor verification tool.
It is used to compare:
1. an original approved document
2. a revised document returned by an intern, contractor, vendor, or outside company

The original is the baseline/source of truth.
The tool must show exactly what changed.

LOCKED PRODUCT RULES
1. Compare Versions is a first-class tool with:
   - its own dashboard card/button
   - its own Tools dropdown entry
   - its own public-site explanation
   - its own demo entry later
2. Workspace is split-screen and document-first:
   - left pane = original/baseline
   - right pane = revised version
3. Both panes must visibly render/scan the documents, not just summarize text
4. There must be an explicit central or primary Scan / Compare action before comparison starts
5. Each selected document must be removable by X/remove before scanning
6. Manager/supervisor notes must be part of the comparison session
7. This tool is not the PDF Editor:
   - Compare Versions verifies changes
   - PDF Editor fixes changes
8. This tool must be planned with future Word-document support in mind
9. The app overall is not PDF-only. Word docs are a first-class accepted document type across PlainPath, even if Compare Versions V1 starts PDF-first

CORE BUSINESS USE CASE
A supervisor asks someone else to update an SOP, manual, contract, policy, or similar document.
Weeks or months later, the revised version comes back.
The supervisor uploads:
- the original
- the revised version
- optional manager notes / watchlist items
Then presses Scan / Compare.
The system identifies what changed and helps determine whether the changes are acceptable.
