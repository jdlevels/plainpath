1. Left pane size and readability

For standard scan tools, use a clear document-first layout:

- Left document pane should be visually dominant and readable.
- Target width: 58–62% left document pane / 38–42% right intelligence panel where feasible.
- Do not let the document viewer feel compressed.
- Use most of the available screen height.
- Keep independent scrolling.

For Compare Versions:
- preserve the three-zone layout, but ensure Original and Revised panels remain readable.
- If needed, reduce the Change Intelligence panel slightly or make it collapsible.

For Redact:
- keep the existing paper-surface layout unless a minor consistency fix is needed.

2. Document viewer header standard

Every loaded tool should clearly show:

- Tool name
- File name
- Document type or detected type
- Page/section count
- Confidence/status badge if applicable
- View controls: Fit / 75% / 100% or equivalent when supported

Examples:

Analyze a Document
File: Commercial Lease Agreement.pdf
Status: Action plan ready · 5 actions · 2 urgent

Document Trust Check

Status: Needs verification · 31/100 trust score

Clause Extractor

This should prevent the issue seen in Clause Extractor where it was not clear what tool was loaded.

3. Processing/loading animation standard

Use the approved Analyze-style document loading animation consistently across scan tools.

During processing, the left pane should show:
- document skeleton/page preview
- animated scan/progress line
- highlighted current section/page
- loading status label
- file name
- tool name
- page/section count if known

The processing animation should be visually consistent across:
- Analyze a Document
- Document Trust Check
- Contract Review
- Clause Extractor
- Compare Versions, modified for two documents
- Redact Sensitive Info, if not already consistent

Do not use a generic blank placeholder if a document preview or skeleton can be shown.

4. Loaded document viewer standard

After processing, the left pane should show a strong document workspace:

- clear document sections or paper preview
- visible source/highlight states
- section/page labels
- active source highlight when a right-panel chip is clicked
- evidence banner when applicable
- footer/page navigation if supported

Avoid:
- large empty dark areas
- tiny text blocks pinned at the top
- unclear document identity
- missing tool/file labels
- inconsistent loading visuals
