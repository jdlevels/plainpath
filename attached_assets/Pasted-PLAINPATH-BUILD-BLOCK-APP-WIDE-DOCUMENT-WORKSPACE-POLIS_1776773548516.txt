==================================================
CONTEXT
==================================================

PlainPath now has multiple document-heavy tools that must feel like real working surfaces, not cramped previews.

Standing product rules already established:
- split-screen is the default rule for creation/editing/review tools
- left pane = live document surface / original document / output preview
- right pane = controls / actions / issue context / editing tools
- single-pane is the exception and must be justified
- document remains visually primary
- visible Save controls should exist where editing occurs
- autosave may support the user, but should not replace explicit save
- letter-size/document-first readability matters on desktop
- mobile should remain responsive, but desktop workspace usability is the priority for this pass

This pass is about making the document-heavy workspaces feel consistently spacious, readable, and production-ready across the app.

==================================================
T001 — WORKSPACE CONSISTENCY AUDIT + NORMALIZATION
==================================================

Goal:
Bring the major document-heavy tools into a coherent, product-consistent workspace model.

Required:
- normalize split-screen behavior where appropriate
- make sure left/right responsibility is consistent:
  - left = document/output/original surface
  - right = controls/context/actions
- remove obvious layout inconsistencies that make one tool feel materially different from the others without reason
- preserve each tool’s purpose, but make the family resemblance strong

Focus on:
- shared structural consistency
- consistent toolbar/header rhythm
- consistent visual priority of the document surface
- cleaner cross-tool mental model

Do not force identical UI if the tool’s function genuinely differs.
Normalize intelligently.

==================================================
T002 — PANE SIZING / SPACING / HEADER HIERARCHY POLISH
==================================================

Goal:
Each workspace should have enough room to actually read, review, and work.

Required:
- tighten pane widths so the document surface has real usable space
- remove wasted horizontal space where it harms readability
- keep right pane wide enough for controls without crushing the document
- reduce oversized headers/blocks/toolbars if they steal too much vertical space
- ensure button groups and metadata do not crowd the top of the workspace
- make desktop layouts feel balanced and deliberate

Specific expectations:
- desktop should favor a roomy letter-size-style reading/editing surface
- right-side action/context areas should be fixed/sensible width where appropriate
- top bars should be compact but clear
- avoid double-wrapping controls that waste space

Do not create brittle pixel-perfect hacks.
Use stable responsive layout logic.

==================================================
T003 — DOCUMENT-FIRST USABILITY IMPROVEMENTS
==================================================

Goal:
The user should always feel that the document itself is central and workable.

Required:
- ensure document preview/canvas/original PDF area is easy to read
- where feasible, show the real uploaded/opened document in scan/progress/review states instead of generic placeholders
- improve scroll/container behavior so document panes feel natural
- make page/document surface visually primary
- improve issue/action-to-document relationship where relevant
- ensure Compare Versions, PDF Editor, and similar surfaces keep the document obvious and central

Also:
- if a tool currently has awkward clipping, narrow panes, or unnecessary scrolling caused by layout rather than document size, fix it
- if a tool’s action panel could be simplified to restore document space, do so carefully
- preserve current functioning workflows

Do not build new major features here.
This is a workspace polish pass.

==================================================
T004 — SAVE / ACTION / CONFIRMATION UX CONSISTENCY
==================================================

Goal:
Editing/review tools should have consistent, trustworthy action patterns.

Required where applicable:
- visible Save button/icon for editing tools
- highlight Save when unsaved changes exist
- keep autosave support where already present, but do not rely on it alone
- uploaded/opened document should remain removable/replacable before processing where product rules require it
- tools that require a pre-run action should clearly hold at a confirmation state until the user clicks the primary action
- primary actions should be obvious and consistently placed
- toolbar/action wording should be practical and not ambiguous

Examples of consistency targets:
- Save vs Export distinction
- Analyze / Review / Check button placement
- remove/replace upload affordance
- non-destructive action emphasis before destructive actions

Do not over-engineer shared components unless there is a clear low-risk win.
