Please implement this targeted refinement into the actual Analyze a Document tool.

Goal:
Restore Analyze a Document’s core value as a document action plan.

The user should clearly see:
- what the document means
- what needs to be completed
- what is missing
- what steps to take next
- what deadlines matter
- who may be responsible
- where each action came from in the document

Implementation requirements:

1. Keep the existing layout.
- Left document viewer
- Right intelligence/action panel
- Source-backed findings
- Clickable source chips
- Premium dark UI
- Mobile Analysis / Document tabs

2. Update the Completed Analyze Overview right panel order:

A. Plain-English Summary
B. Action Plan Snapshot
C. Step-by-Step Required Actions
D. Missing Items / Information Needed
E. Deadlines & Time-Sensitive Items
F. Key Risks / Watchouts
G. Source Traceability

3. Add Action Plan Snapshot.

Show compact chips/cards such as:
- actions found
- urgent actions
- missing items
- deadlines found
- source-backed findings
- overall status: Ready / Needs completion / Needs review

4. Strengthen Step-by-Step Required Actions.

Each action card should include:
- step number
- action title
- plain-English instruction
- why it matters
- priority: urgent / important / optional
- status: not started / in progress / complete
- responsible party if known
- deadline if known
- source chip

This should be the strongest section in Analyze a Document.

5. Add Missing Items / Information Needed.

Each missing item should include:
- missing item title
- why it matters
- how to resolve it
- source chip if available

Use cautious wording:
- appears missing
- may need verification
- not found in the provided document
- confirm before acting

6. Strengthen Deadlines & Time-Sensitive Items.

Each deadline card should include:
- date or timeframe
- what it applies to
- consequence if stated
- priority
- source chip

7. Keep Key Risks / Watchouts secondary.

Analyze a Document should not become Contract Review or Trust Check.

The main identity is:
- understand the document
- know what must be completed
- know what is missing
- know what to do next

8. Source chip behavior must work for action steps.

When clicked:
- scroll the left document viewer to the relevant section
- highlight the source section
- show the evidence banner
- keep the related action card active

9. Completion status UI.

Show action statuses:
- Not started
- In progress
- Complete

If full persistence is not already easy, implement this as local/session UI for now. Do not block implementation on account-level persistence.

10. Low Confidence State.

Preserve the partial action plan concept.

Use:
- what PlainPath could read
- what could not be verified
- partial required actions
- recommended next steps

11. Mobile behavior.

Mobile Analysis tab order:
- Plain-English Summary
- Action Plan Snapshot
- Step-by-Step Required Actions
- Missing Items
- Deadlines
- Key Risks
- Source chips

Document tab remains second.

12. Preserve safe wording.

Avoid:
- guaranteed outcome
- legal advice
- must sign
- must pay
- legally required unless clearly stated in the document

Use:
- based on the document
- appears to require
- verify before acting
- source-backed next step
- consider professional review if high-risk
