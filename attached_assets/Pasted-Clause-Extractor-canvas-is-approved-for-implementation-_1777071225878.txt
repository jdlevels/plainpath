Implementation requirements:

1. Follow the approved PlainPath Scan Workspace Standard.
- Left panel: document viewer, about 55–60%
- Right panel: Clause Extraction panel, about 40–45%
- Both panels should support independent scrolling
- Mobile should use Clauses tab first, Document tab second

2. Preserve all approved states:
- Empty State
- Processing State
- Completed Clause Extraction Overview
- Source chip active / clause highlighted state
- Low Confidence State
- Error State
- Mobile Clauses View
- Mobile Document View

3. Completed Clause Extraction panel order:
A. Extraction Summary
B. Clause / Confidence Strip
C. Key Extracted Clauses
D. Clause Categories / Filters
E. Obligations & Owners
F. Dates / Deadlines
G. Missing / Unclear Clauses
H. Source Traceability

4. Keep Clause Extractor distinct from Contract Review.
This tool should focus on:
- extracting clauses
- organizing clauses by category
- identifying obligations
- identifying owners/responsible parties
- identifying dates/deadlines
- linking extracted clauses back to source text

Risk should be secondary, not the main identity.

5. Use extraction-focused wording.
Use:
- extracted clause
- clause category
- source-backed extracted term
- term to verify
- possible missing clause
- unclear term
- not legal advice

Avoid:
- legal conclusion language
- you should sign / you should not sign
- legally invalid
- guaranteed protection
- risk-review dashboard language

6. Source chips must be functional.
When clicked:
- scroll the document viewer to the referenced clause/section
- highlight the matching clause
- show the evidence banner
- keep the related clause card active
- preserve active source-chip state

If exact coordinates are not available:
- scroll to the closest matching section
- highlight the nearest matching text block

7. Category filters should work visually and logically.
Include categories such as:
- All
- Payment
- Termination
- Obligations
- Liability
- Confidentiality
- Deadlines
- Missing / Unclear

8. Obligations & Owners should use structured extracted data.
Each item should show:
- obligation
- responsible party
- deadline/date if available
- source chip

9. Dates / Deadlines should use compact timeline/list format.
Each item should show:
- date or deadline
- what it applies to
- notice period if relevant
- source chip

10. Low-confidence message must use:
“PlainPath could extract part of this document, but the scan quality limits extraction confidence.”

11. Error state message must use:
“Clause extraction could not be completed.”

Actions:
- Try again
- Upload different file
- Ask This Document
- Analyze a Document

12. Use fictional demo/mock content only.
No real company names, real people, real account numbers, or real contract examples.

13. Keep visual hierarchy calm.
- Purple for source evidence and traceability
- Green for successfully extracted/clear items
- Amber for unclear or needs review
- Red only for high-priority urgent items
- Avoid dense report layouts
