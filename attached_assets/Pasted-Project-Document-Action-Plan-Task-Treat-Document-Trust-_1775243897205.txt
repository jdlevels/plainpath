Primary objective:
Mark the current Phase 2 Trust Check implementation as:
LOCKED FOR PILOT USE

Then complete the following pilot-readiness tasks:

1. Pilot baseline confirmation
Confirm and preserve the current Trust Check behavior as the pilot baseline:
- three-score summary remains unchanged unless a real bug is found
- result section order remains aligned to the final Phase 2 requirements
- no new score dimensions are added
- no cosmetic redesigns are introduced

2. Pilot document pack validation
Run the current Trust Check system against a pilot-style document pack including:
- fake utility shutoff notice
- fake IRS/government-style warning
- fake debt collection letter
- realistic fictional auto loan contract
- legitimate utility notice
- one additional ordinary low-risk legitimate document if helpful

For each document, capture:
- Primary verdict
- Authenticity Risk
- Document Risk
- Verification Confidence
- key scam indicators found
- key contract/document risk terms found
- metadata findings if applicable
- structural findings if applicable
- what to verify
- safe next steps

3. Pilot output review
For each pilot document, confirm:
- score behavior is reasonable
- verdict behavior is reasonable
- metadata behavior is appropriate
- structural findings are specific and useful
- no duplicated findings appear
- no overclaiming certainty
- the result is readable for a normal end user
- the result would be useful in a police-department pilot review

4. Stability check
Reconfirm:
- `/import?mode=trust-check` still works
- upload works
- paste works
- demo mode works
- standard Analyze a Document mode still works
- no tab/paywall restrictions interfere
- no console errors are present
- no empty metadata section appears on pasted text
- no broken layouts on desktop or mobile in touched areas

5. Pilot-ready documentation output
Prepare a compact pilot summary of what Trust Check currently does.

The pilot summary should explain that the feature can currently assess:
- scam / authenticity signals
- risky contract/document terms
- verification confidence
- metadata anomalies where available
- structural inconsistencies where present
- deadlines / pressure tactics
- suspicious contact/payment instructions

The pilot summary should also make clear:
- results are risk-based, not absolute proof
- documents can be genuine-looking yet still contain harmful terms
- the tool is intended to support review and verification, not replace official legal or forensic determination

In this pass, only fix issues if:
- a real bug is found

- add image/pixel forensics
