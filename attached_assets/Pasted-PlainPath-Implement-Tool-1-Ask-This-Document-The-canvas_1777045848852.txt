PlainPath — Implement Tool 1: Ask This Document

The canvas/design pass for Ask This Document is approved.
Build the real feature now, using the approved UX as the implementation blueprint.

This is a SINGLE-DOCUMENT Q&A tool.
Do not mix in:
- multi-document chat
- packet splitting
- obligation tracker
- signature features
- SOP/manual creation
- compare-versions logic

Keep the scope tight and production-quality.

## Tool identity
Name:
Ask This Document

Subtitle:
Ask questions about one document and get source-backed answers

Core promise:
The user uploads one document, asks natural-language questions, receives grounded answers based only on that document, and can jump to the exact supporting source sections.

---

## Product requirements

### 1. Main layout
Implement the approved document-first split-screen workspace on desktop:

- Left: document viewer
- Right: Ask This Document answer panel

The left document viewer should remain the dominant content surface.
Do not let the right panel visually overpower the document.

### 2. Required user states

#### A. Empty state
Before upload:
- show the approved title/subtitle
- show upload area
- supported file note
- suggested prompt chips
- helper line:
  “Ask about dates, obligations, risks, fees, renewal terms, deadlines, or next steps.”

#### B. Loaded state / no question yet
After upload:
- document visible in left viewer
- suggested question chips shown in right panel
- quick actions visible:
  - Summarize
  - Key Dates
  - Risks
  - Obligations
  - Plain English

#### C. Answer state
When a user asks a question:
- top answer summary block
- source-backed findings section
- follow-up questions section
- answer must be clearly grounded in the uploaded document only

#### D. Loading state
Use the approved refined loading treatment:
- stable layout
- no flashing
- status/progress language such as:
  - Reading document structure
  - Locating relevant clauses
  - Generating source-backed answer

#### E. Low-confidence / no-answer state
If the system cannot clearly answer from the document:
- do not fabricate an answer
- say the answer was not clearly found in the uploaded file
- suggest improved next prompts
- visually distinguish this from true system errors

#### F. Error state
If there is a system failure:
- show a clean retry state
- no raw error dumps
- no broken layout

---

## Viewer requirements

### 3. Left document pane
Implement a real document viewer with:
- file name
- page controls
- zoom
- fit width / fit page
- page count
- active source indicator when a citation is selected

The document must be readable and usable.
Do not shrink the document excessively.

### 4. Citation behavior
This is a core feature and must feel premium.

When the user clicks a citation/source chip:
- auto-scroll the document viewer to the matching section
- visibly highlight the supporting text block
- show page number / source label
- make the citation feel clearly interactive

If practical, add a hover/tap preview behavior for citations showing page/section info.

### 5. Mobile behavior
On mobile, use the approved stacked approach:
- Document tab
- Ask tab

Requirements:
- clear tab switch between Document and Ask
- tapping a citation in Ask should jump the user to the corresponding source in Document
- preserve the source highlight when they switch views

---

## Answer quality rules

### 6. Grounding / answer behavior
Answers must be based only on the uploaded document.
Do not answer from general world knowledge when the answer is not clearly supported by the file.

The answer system should prefer:
- direct answer summary
- clearly separated supporting findings
- traceable citations/source chips
- suggested follow-up questions

If the answer is uncertain, say so clearly.

### 7. Suggested prompt behavior
Suggested prompt chips should be contextual and practical.
Seed with examples such as:
- What are my obligations?
- When does this expire?
- What are the payment terms?
- What happens if I miss a deadline?
- Who owns the IP?
- What are the termination conditions?

### 8. Visual quality
Keep the implemented UI aligned with the approved canvas:

- clear interaction states

### 9. Stability
This tool must not introduce:
- flashing screens
- layout jumps
- broken loading states
- dead citation clicks
- stale document highlight states

### 10. Scope control
Do not add extra features in this pass.
No:
- multi-file support
- cross-document answers
- saved conversations across files
- admin-only extras
- training/manual features
- signature workflows

Build only the approved single-document Ask This Document experience.
