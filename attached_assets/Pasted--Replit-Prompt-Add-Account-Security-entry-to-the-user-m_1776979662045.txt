### 4. Password management behavior
If the user is signed in and knows their password:
- provide Change password inside Account & Security

If the user forgot their password:
- provide Reset password / Forgot password path
- route that flow correctly using Clerk-supported reset behavior

### 5. Keep Support focused
Support should remain for:
- help/contact

- billing help / subscription help

Do not make Support the main home for password management.

### 6. Keep current account-deletion decision
Do NOT turn on or expose self-service account deletion for existing users in this pass.
If there is any placeholder text for deletion, remove it or keep it hidden until the real app-side deletion workflow is ready.

### 7. Maintain consistency with current auth configuration
Current Clerk config now supports:
- email
- username

The new Account & Security surface should reflect that cleanly without introducing conflicting terminology.
