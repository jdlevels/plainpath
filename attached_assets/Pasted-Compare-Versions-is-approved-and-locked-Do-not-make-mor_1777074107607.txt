Do not add Document Classifier or Packet Splitter.

Use the approved PlainPath Scan Workspace Standard and the locked Analyze, Trust Check, Contract Review, Clause Extractor, and Compare Versions designs as the visual baseline.

Goal:
Redesign Redact Sensitive Info so it feels like the same premium PlainPath system, but focused specifically on detecting sensitive information, helping the user review each item, applying redactions safely, and exporting a clean redacted copy.

Important:
Redact Sensitive Info should use a modified scan-workspace layout because it has document review + redaction controls.

Core layout:
- Premium dark UI
- Document-first layout
- Left document viewer
- Right Redaction Control panel
- Source-backed detected sensitive items
- Clickable sensitive-item chips
- Manual review before final export
- Compact cards, not report dumps
- Clear original-vs-redacted behavior
- Visible Save / Export controls

Desktop layout:
- Left panel: document viewer, about 60%
- Right panel: redaction controls, about 40%
- Both panels should scroll independently
- Use most of the visible screen height

Mobile layout:
Use tabs:
- Redactions
- Document

Default mobile view should open on Redactions first.
Document should remain one tap away.

Design the following canvas states:

1. Empty State — before upload

Purpose:
The user uploads a document to detect and redact sensitive information.

Suggested headline:
“Find and redact sensitive information.”

Suggested subtext:
“Upload, paste, or scan a document. PlainPath identifies possible sensitive details, lets you review each item, and helps create a redacted copy for safer sharing.”

Input options:
- Upload PDF / DOCX
- Paste Text
- Scan Photo
- Import Link, if currently supported

Works well with:
- contracts
- forms
- letters
- invoices
- legal documents
- HR documents
- financial records
- medical or insurance forms
- official notices

Use cautious wording:
- “possible sensitive information”
- “review before redacting”
- “redacted copy”
- “does not replace manual review”

2. Processing State — sensitive info scan in progress

Use left document preview and right progress panel.

Progress checklist:
- Reading document structure
- Detecting names and contact details
- Finding financial or account details
- Checking IDs, dates, and personal data
- Grouping sensitive items by category
- Preparing redaction review

3. Completed State — Redaction Review

Right panel order:

A. Redaction Summary
- 4–6 lines maximum
- explain how many possible sensitive items were found
- identify the main categories
- remind user to review before export

B. Detection / Confidence Strip
Use compact chips:
- Sensitive items found
- Review confidence
- Categories found
- High-priority items
- Items selected for redaction

C. Suggested Redactions
Show top sensitive findings by default.
Each card should include:
- detected item label
- category
- masked preview, not full exposed value when possible
- one-line reason
- confidence chip
- source chip
- checkbox or toggle to include/exclude from redaction

D. Redaction Categories
Use filters or grouped sections:
- Names
- Addresses
- Phone / Email
- Account / Financial
- IDs / Reference Numbers
- Dates
- Signatures
- Other

E. Review Queue
Show:
- selected for redaction
- needs user confirmation
- ignored / left visible
- manually added redactions

F. Manual Redaction Tools
Include clear controls:
- add manual redaction box
- select text to redact
- undo last redaction
- clear all manual redactions
- preview redacted copy

G. Export / Save Controls
Include:
- Save
- Export redacted PDF
- Export redacted DOCX if supported
- Download redacted copy
- Keep original unchanged

Important:
The UI should clearly state that the original document is not destroyed. Redactions create a separate redacted copy.

H. Source Traceability
Every detected item should have source chips.
Source chips should scroll/highlight the document location.

4. Sensitive Item Active State

Show what happens when a user clicks a sensitive-item/source chip.

Behavior:
- chip becomes active
- matching item highlights in the document viewer
- document scrolls to the relevant page/section
- evidence banner shows the detected category, not necessarily the full sensitive value
- related redaction card remains active
- selected redactions show a dark/redaction overlay preview

5. Redaction Preview State

Show what the document looks like after selected redactions are applied.

Behavior:
- document viewer shows black redaction blocks over selected sensitive items
- right panel shows selected item count
- user can toggle between:
  - Original View
  - Redaction Preview
- user can still undo or adjust before export
- export button is visible but not forced

6. Low Confidence / Partial Detection State

Use when scan quality is weak.

Suggested message:
“PlainPath could detect part of this document, but scan quality limits redaction confidence.”

Show:
- confidence badge
- what was readable
- what could not be verified
- warning that manual review is required
- recommended next steps

Actions:
- Upload clearer PDF
- Upload original file
- Upload text-based version
- Continue with partial detection
- Ask This Document

7. Error State

Clean retry state.

Message:
“Sensitive information scan could not be completed.”

Actions:
- Try again
- Upload different file
- Ask This Document
- Analyze a Document

8. Mobile Redactions View

Mobile should show:
- redaction summary
- detection/confidence strip
- suggested redactions
- category filters
- review queue
- preview/export controls
- compact cards

9. Mobile Document View

Show document viewer with:
- active sensitive-item highlight
- redaction preview toggle
- evidence banner
- easy return to Redactions tab

Design rules:
- Do not make this a long report page.
- Do not auto-redact without user review.
- Do not show full sensitive values unnecessarily.
- Do not imply perfect detection.
- Use “possible sensitive information,” “review before export,” and “manual review required.”
- Keep the original document unchanged.
- Redactions should create a separate redacted copy.
- Keep source chips highly visible.
- Keep the interface calm, credible, and professional.

Color usage:
- purple = PlainPath source traceability / active item
- amber = needs user review
- red = high-priority sensitive item only
- green = selected/confirmed for redaction
- gray/black = applied redaction overlay
- blue = neutral action/help

Editing/save rule:
Because Redact Sensitive Info is an editing/export tool:
- include a visible Save button/icon
- show unsaved-change state when redactions are modified
- include a clear Export Redacted Copy action
- do not rely only on autosave
