2. THREE DETERMINISTIC COMPARISON STAGES
==================================================

Implement all three.

----------------------------------------
Stage A — Visual diff
----------------------------------------

Mechanism:
- render each page of both PDFs to PNG/images at fixed DPI (150 dpi approved)
- compare same-position pages only in Slice 3
- use pixelmatch or equivalent deterministic pixel diff
- cluster changed pixels into bounding rects using connected-component grouping or equivalent
- output page-level visual changes

Rules:
- page pairing is positional only in V1:
  page 1 ↔ page 1
  page 2 ↔ page 2
  etc.
- if revised has extra trailing pages -> added_page
- if original has extra trailing pages -> removed_page
- changed page with pixel delta below cosmetic threshold (<1%) = unchanged
- changed page with meaningful delta -> changed rects emitted

Output per visual item:
{
  id,
  source: "visual",
  page_original,
  page_revised,
  rect_original: { x, y, w, h } | null,
  rect_revised: { x, y, w, h } | null,
  change_type: "visual_change" | "added_page" | "removed_page",
  signal_type: null,
  original_text: null,
  revised_text: null,
  severity: "high" | "medium" | "low",
  severity_overridden: false,
  ai_explanation: null,
  ai_category: null,
  meta: {
    pixel_delta_pct: number
  }
}

Coordinate model:
- fractional x/y/w/h
- top-left origin
- per-pane independent coordinates allowed later, but for Slice 3 use page-relative fractional coordinates compatible with rendering overlays

----------------------------------------
Stage B — Text diff
----------------------------------------

Mechanism:
- extract text per page from both PDFs
- split into line-level or text-block-level units
- diff using deterministic algorithm only (Myers diff / LCS / equivalent)
- identify:
  - text_added
  - text_removed
  - text_modified
- compute approximate bounding rects from available PDF text position data when possible
- if position data is weak, still emit text diff item with page references and null rects rather than skipping

Output per text item:
{
  id,
  source: "text",
  page_original,
  page_revised,
  rect_original,
  rect_revised,
  change_type: "text_added" | "text_removed" | "text_modified",
  signal_type: null,
  original_text: "...",
  revised_text: "...",
  severity: "high" | "medium" | "low",
  severity_overridden: false,
  ai_explanation: null,
  ai_category: null,
  meta: {
    edit_distance?: number
  }
}

Do not call OpenAI.
Do not classify meaning semantically in this slice.

----------------------------------------
Stage C — Structural signals
----------------------------------------

Mechanism:
Use extracted text and simple heuristics to detect structural changes:
- page_count_change
- heading_added
- heading_removed
- heading_renamed
- section_reordered
- table_added
- table_removed
- appendix_added
- appendix_removed
- signature_block_changed
- version_history_changed
- header_footer_changed

Use deterministic pattern detection only:
- heading heuristics from capitalization / numbering / line shape / pdf font hints if available
- signature block via label patterns like "Signature", "Approved by", "Signed", etc.
- appendix/version history via common labels
- table heuristics from aligned multi-column lines / extracted table-like structure if available

Output per structural item:
{
  id,
  source: "structural",
  page_original,
  page_revised,
  rect_original,
  rect_revised,
  change_type: "structural_signal",
  signal_type: "page_count_change" | "heading_added" | "heading_removed" | "heading_renamed" | "section_reordered" | "table_added" | "table_removed" | "appendix_added" | "appendix_removed" | "signature_block_changed" | "version_history_changed" | "header_footer_changed",
  original_text: "...",
  revised_text: "...",
  severity: "high" | "medium" | "low",
  severity_overridden: false,
  ai_explanation: null,
  ai_category: null,
  meta: {}
}

4. DETERMINISTIC SEVERITY RULES
==================================================

Implement rule-based severity only.

HIGH when any of the following apply:
- financial value change detected
  regex examples: $, USD, %, percent, fee, rate, price, total, amount
- date/deadline change
  keywords/patterns: effective, expires, due, deadline, date formats
- legal clause language change
  keywords: shall, liable, indemnify, warranty, terminate, breach
- policy/compliance language change
  keywords: must, required, prohibited, compliance, regulation
- safety threshold/limit change
  keywords: maximum, minimum, limit, threshold, psi, ppm
- signature_block_changed
- heading_removed for an entire section of substance
- removed_page

MEDIUM when:
- text_modified but not matching high rules
- table_added or table_removed
- heading_renamed
- section_reordered
- appendix_added or appendix_removed
- added_page
- visual_change > 10% on a page with no matching high trigger

LOW when:
- small text substitution / punctuation / typo-like edit
- header_footer_changed only
- formatting-like visual change with low delta
- visual_change > 0 but < 3% with no text match

Manager override UI does NOT need to be implemented in this slice unless it comes nearly free.
If not already in place, defer actual override controls to Slice 4.
But keep the data field severity_overridden in the schema output.
