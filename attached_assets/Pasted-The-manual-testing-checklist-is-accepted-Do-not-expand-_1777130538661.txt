Goal:
Every PlainPath tool that uploads or processes a PDF should show the same loading experience so the app feels unified and professional.

Apply to:
- Analyze a Document
- Document Trust Check
- Contract Review
- Clause Extractor
- Compare Versions
- Redact Sensitive Info
- Build a Contract / Document Builder only if it uploads/imports a source PDF

Standard loading animation requirements:

1. Tool identity must be visible
Every loading state should clearly show:
- PlainPath mark/header
- tool name
- uploaded file name
- document type if known
- current status badge

2. Left document loading preview
The left side should show a consistent document skeleton/page preview:
- dark document workspace
- page/card skeleton
- animated scan/progress line
- highlighted current section/page
- subtle pulse animation
- file name visible near the preview

Avoid:
- blank dark screens
- generic spinners only
- inconsistent loading cards
- hidden file names
- unclear tool identity

3. Right-side progress checklist
Where the tool has a right panel, show a consistent progress checklist.

Use this structure:
- Reading document
- Extracting text
- Identifying key sections
- Running tool-specific analysis
- Building results

Tool-specific final step examples:
- Analyze: Building action plan
- Trust Check: Checking trust signals
- Contract Review: Reviewing terms and risks
- Clause Extractor: Extracting clauses
- Compare Versions: Aligning document changes
- Redact: Detecting sensitive information

4. Progress bar and status
Use the same visual pattern:
- progress bar
- percentage or step count where available
- active step highlighted
- completed steps checked
- pending steps dimmed

5. Reusable component preferred
If possible, create or reuse one shared component such as:

DocumentProcessingScreen
or
PDFProcessingWorkspace

Props should support:
- toolName
- fileName
- documentType
- currentStep
- steps[]
- progress
- accentColor if needed
- leftPreviewMode: single / compare / paper
- statusLabel

Do not duplicate separate loading designs across tools if a shared component can support them cleanly.

- uploaded file
