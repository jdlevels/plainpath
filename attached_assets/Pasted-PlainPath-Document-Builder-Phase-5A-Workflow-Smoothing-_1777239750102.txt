PlainPath Document Builder — Phase 5A Workflow Smoothing: Direct Canvas + Invisible Alignment Grid

Goal:
Make Document Builder feel fast, smooth, and premium by letting users work directly on the left document page instead of relying only on the right panel.

Product rule:
The left document page is the primary work surface.
The right panel supports the selected object.
The user should be able to click, add, edit, move, resize, duplicate, and delete fields directly on the document page.

Important:
The left page should feel flexible and fast, but still preserve document/page boundaries so content does not disappear, break save behavior, or make future export impossible.

Add:
- Direct canvas selection
- Inline editing
- Floating mini-toolbar
- Add-block-here control
- Insert-anywhere fields
- Drag/move
- Resize where safe
- Duplicate/delete
- Invisible alignment grid / snap grid
- Accessibility fallback controls

Core requirement:
The left document preview must no longer behave like a read-only preview. It must become an active editable canvas.

Build this as a safe first version:
- direct click selection
- inline text editing
- add text box anywhere
- drag/move text box
- resize text box if feasible
- duplicate/delete text box
- save/reload text box
- preserve existing structured sections
- invisible alignment/snap grid

1. Direct page selection
- Clicking any visible block on the left page selects it.
- Selected block shows a premium outline/ring.
- Right panel updates to that selected block.
- Selection persists across tabs.

2. Inline editing
- Double-click heading, paragraph, note, callout, or text box to edit directly on the page.
- Blur or Enter saves the change.
- Escape cancels if feasible.
- Existing right-panel editing remains working.
- Autosave is triggered through the current save flow.

3. Floating mini-toolbar
When a block or freeform field is selected, show a compact floating toolbar near the selected object:

- Edit
- AI
- Duplicate
- Delete
- Move
- Style

All buttons must use type="button".

4. Add block here
When hovering between sections or clicking empty space inside the page, show:

“+ Add block here”

Add block options:
- Heading
- Paragraph
- Step-by-step procedure
- Checklist
- Warning / Caution
- Image / Screenshot placeholder
- Signature line
- Date field
- Approval field
- Revision history
- Table
- FAQ
- Divider
- Text box
- Logo/image placeholder
- Callout/note

5. Insert anywhere
- User can click inside the page and insert a block or field at that location.
- Keep items inside page boundaries.
- Do not require the user to start from the right panel.
- Inserted items should appear where the user clicked, adjusted only enough to keep them inside the page.

6. Invisible alignment grid / snap grid
Add a hidden alignment grid to the document page.

Requirements:
- Grid should help align text boxes, fields, logos, callouts, signatures, dates, and other freeform objects.
- Grid should not be visibly shown by default.
- Objects should snap to the hidden grid when moved or resized.
- Use a practical grid size, for example 8px or 10px.
- Add a small optional toggle later if easy:
  “Show guides”
  but default should be hidden.
- If “Show guides” is implemented, it should show faint guide lines only while editing, not in export or saved document output.
- Snapping should feel helpful, not restrictive.
- User can still place items freely inside the page; snap only cleans alignment.

Recommended behavior:
- During drag: snap x/y to grid.
- During resize: snap width/height to grid.
- During insert: initial x/y should snap to nearest grid point.
- Keep all fields inside page bounds.
- Do not show the grid in PDF/DOCX export later unless explicitly designed as an editing-only guide.

7. Freeform field model
Add a backward-compatible freeform field layer inside the existing content object.

Use:

content.freeformFields

Each freeform field should include:
- id
- type
- pageNumber
- x
- y
- width
- height
- text/value
- style
- zIndex if layering is implemented

No DB schema changes.
Older drafts without freeformFields must still load.

8. Drag/move
For freeform fields:
- User can drag the field around the page.
- Store x/y relative to the page.
- Snap x/y to the hidden grid.
- Keep movement inside page bounds.
- Show visual drag feedback.
- Do not let fields disappear outside the page.

9. Resize
For text boxes, callouts, logo/image placeholders, and signature fields:
- Add resize handles if feasible.
- Store width/height.
- Snap width/height to hidden grid.
- Keep minimum usable size.
- Keep inside page bounds.

10. Duplicate/delete
- Duplicate selected block/field.
- Delete selected block/field.
- Confirm destructive delete only if needed.
- No document reset.

11. Accessibility fallback
Dragging must not be the only way to reposition objects.

Add at least one non-drag fallback:
- x/y/width/height fields in the right panel
or
- nudge buttons: up, down, left, right
or
- click-to-place mode where the user selects a field type, then clicks the desired destination

The fallback should also respect page bounds and grid snapping.
