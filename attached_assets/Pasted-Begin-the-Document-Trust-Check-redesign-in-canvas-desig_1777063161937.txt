Begin the Document Trust Check redesign in canvas/design mode only.

Do not implement into the live app yet.
Do not start any other tools.
Do not add SOP/manual builder language.
Do not add Document Classifier or Packet Splitter.

Use the approved PlainPath Scan Workspace Standard and the locked Analyze a Document design as the visual baseline.

Goal:
Redesign Document Trust Check so it feels like the same premium PlainPath system, but focused specifically on document authenticity, credibility, manipulation risk, and trustworthiness.

Core layout:
- Premium dark UI
- Document-first layout
- Left document viewer
- Right trust intelligence panel
- Source-backed findings
- Clickable source chips
- Compact cards, not report dumps
- Overview-first flow before deeper details

Desktop layout:
- Left panel: document viewer, about 55–60% width
- Right panel: trust intelligence panel, about 40–45% width
- Both panels should scroll independently
- Use most of the visible screen height

Mobile layout:
- Tabs: Trust Check first, Document second
- Default mobile view should show the trust findings first
- Document tab should remain one tap away

Design the following canvas states:

1. Empty State — before upload
Purpose:
The user uploads a document to check whether it appears trustworthy.

Suggested headline:
“Check whether a document can be trusted.”

Suggested subtext:
“Upload, paste, or scan a document. PlainPath checks for credibility signals, missing details, suspicious structure, conflicting information, and source-backed red flags.”

Input options:
- Upload PDF / DOCX
- Paste Text
- Scan Photo
- Import Link, if currently supported

Works well with:
- contracts
- notices
- letters
- invoices
- agreements
- forms
- records
- court or official-looking documents

Avoid language that says PlainPath proves a document is real. Use careful language:
- “trust signals”
- “risk indicators”
- “possible red flags”
- “requires human verification”
- “not a legal or forensic determination”

2. Processing State — trust scan in progress
Use left document preview and right progress panel.

Progress checklist:
- Reading document structure
- Checking identity and document type
- Reviewing dates, names, and parties
- Looking for inconsistencies
- Checking formatting and source signals
- Generating trust summary

Keep it compact and premium.

3. Completed State — Trust Overview
This is the main screen.

Right panel order:
A. Trust Summary
- 4–6 lines maximum
- Say whether the document appears low-risk, needs review, or has major trust concerns
- Do not overstate certainty

B. Trust Score / Confidence Strip
Use compact chips:
- Trust score
- Confidence level
- Document type confidence
- Critical red flags count
- Needs human review

C. Major Trust Concerns
Top 3–5 findings only by default.
Each card should include:
- short concern title
- one-line explanation
- severity chip
- source chip
- recommended action

D. Verification Checklist
Action-oriented checklist:
- confirm sender/source
- compare names and dates
- verify signatures or official identifiers
- confirm payment/request details
- request original/source copy if needed
- save evidence

E. Document Consistency
Compact section checking:
- names
- dates
- addresses
- amounts
- signatures
- referenced attachments
- formatting consistency

F. Metadata / Structure Signals
If available:
- file type
- page count
- creation/modification clues
- scan quality
- OCR confidence
- missing metadata
- unusual structure

G. Source Traceability
Every major trust concern should have source chips.
Source chips should scroll/highlight the document section.

4. Source Chip Active State
Show what happens when a user clicks a source chip.

Behavior:
- source chip becomes active
- matching section in left document viewer highlights
- document scrolls to matching section/page
- evidence banner shows the matched text
- related trust concern remains active in the right panel

5. Low Confidence / Partial Trust Scan State
Use when the scan quality is weak.

Suggested message:
“PlainPath could review part of this document, but the scan quality limits trust confidence.”

Show:
- confidence badge
- reason for low confidence
- what could not be verified
- recommended next steps

Actions:
- Upload clearer PDF
- Upload original file
- Upload text-based version
- Continue with partial trust scan
- Ask This Document

6. Error State
Clean retry state.

Message:
“Trust check could not be completed.”

Actions:
- Try again
- Upload different file
- Ask This Document
- Analyze a Document

7. Mobile Trust View
Mobile should show:
- trust score
- top concerns
- verification checklist
- source chips
- compact cards
- Document tab available

8. Mobile Document View
Show document viewer with:
- active source highlight
- evidence banner
- source chip jump behavior

Design rules:
- Do not make this a long report page.
- Do not show every extracted detail expanded by default.
- Do not claim the document is real or fake with certainty.
- Use “signals,” “indicators,” “possible concern,” and “needs verification.”
- Keep the interface calm, credible, and professional.

Color usage:
- green = no obvious concern / verified signal
- amber = needs review / caution
- red = critical inconsistency or high-risk signal
- purple = PlainPath source traceability
- blue = neutral action/help

- Source chip active/highlighted state
- Low Confidence State
- Error State
