## Replit Prompt — Remove Digital Signature from PlainPath completely

We are removing the Digital Signature tool entirely from PlainPath.

This is no longer a featured tool, no longer part of pricing, no longer part of access tiers, and no longer part of the product surface.

This is a full product removal pass, not a cosmetic hide-only pass.

---

## Goal
Remove the Digital Signature / E-Signature feature completely from PlainPath in a clean, production-safe way.

After this pass:
- users should not see the tool anywhere
- no nav/menu/card/demo/pricing/FAQ/billing page should reference it
- no entitlement/access logic should count it
- no broken routes or dead links should remain
- no loading errors tied to signature requests should remain
- product should now reflect 7 tools, not 8

---

## Required removal scope

### 1. Remove from primary UI surfaces
Remove Digital Signature completely from:
- Tools dropdown
- Dashboard tools grid/cards
- Marketing homepage tool pills/cards
- Features section
- Demo/live example sections
- Pricing page / pricing tables
- Billing page “Tool Access”
- FAQs
- Support references
- Any onboarding/help/tutorial references
- Any “8 tools” copy that is only true because Digital Signature was included

Update all counts and copy accordingly:
- 8 tools -> 7 tools
- any “all 8 tools” messaging -> “all 7 tools”
- remove any signature-specific marketing copy

### 2. Remove the route and navigation targets
Remove or disable all app routes/pages for the signature tool, including any:
- /app/signature
- /signature
- /demos/signature
- direct deep links
- route registrations
- menu/nav link targets

If a user somehow hits an old signature URL, redirect gracefully to:
- Tools page
or
- Dashboard
Do not leave a broken page.

### 3. Remove entitlement/gating logic
Remove Digital Signature from all entitlement logic, including:
- Starter / Pro access lists
- Billing tool-access cards
- upgrade gating
- demo availability logic
- access-tier checks
- route guards
- internal tool counts

The product should now behave as a 7-tool system.

### 4. Remove feature-specific loading/API usage
Remove signature-specific frontend and backend behavior, including:
- signature request loading
- send-for-signature actions
- embedded signing/requesting logic
- signature templates
- request inbox/status logic
- signature-specific API routes
- signature-specific hooks/services/components

Important:
Do not leave behind a route or component that still tries to fetch signature requests and throws errors.

### 5. Clean up branding and terminology
Remove these labels from user-facing UI:
- Digital Signature
- E-Signature
- Send for Signature
- Signature requests
- Signed documents
- Audit trail for signatures
- signer / recipients / signature fields (if only related to this removed feature)

Only remove terminology where it belongs to the removed tool.
Do not disturb unrelated document language elsewhere.

### 6. Database / backend cleanup strategy
Audit all backend/database objects related only to the signature feature.

If removing them fully is safe, remove them.
If full deletion is risky right now, do this instead:
- disconnect them from the live product
- stop all reads/writes
- mark them as deprecated/internal
- ensure no active code path depends on them

Do not break migrations or unrelated features.

### 7. Store-prep / documentation cleanup
Update all internal docs and store-prep files so PlainPath is consistently described as a 7-tool product.
Check:
- metadata docs
- store listing docs
- screenshot plans
- feature inventories
- launch checklists
- internal architecture notes
- replit.md or equivalent product notes if tool inventory is listed there

### 8. Preserve layout quality after removal
After removing the tool:
- rebalance tool grids/cards so no empty visual holes remain
- ensure rows/columns still look intentional
- ensure spacing and counts feel premium
- do not leave odd one-off alignment caused by removing one card

### 9. Redirect / fallback behavior
Any old signature entry point must do one of these:
- redirect to dashboard/tools
- show a clean “This tool has been retired” message and link back
Preferred: redirect cleanly.

Do not leave 404-style confusion.

## Safety requirements
- Do not disturb the other core tools
- Do not change auth logic except where signature access was referenced
- Do not change billing logic except to remove signature from access/pricing/tool counts
- Do not introduce regressions to the 7 remaining tools
