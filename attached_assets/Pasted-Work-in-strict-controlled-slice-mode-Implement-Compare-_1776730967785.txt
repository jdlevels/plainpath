==================================================
C. AI SEVERITY UPGRADE LOGIC
==================================================

Critical rule:
AI may upgrade severity.
AI may NOT downgrade below the deterministic baseline.

This means:
- deterministic High stays High always
- deterministic Medium may become High
- deterministic Low may become Medium or High
- if AI thinks something is less serious, ignore that and preserve deterministic severity

Manager override still wins over AI.
Order of precedence:
1. manager override
2. AI-upgraded severity
3. deterministic severity baseline

Implementation suggestion:
Store:
- severity_deterministic
- severity_ai (nullable)
- severity_effective derived in UI/backend
If current model already uses severity + override flag, adapt cleanly but preserve source-of-truth clarity.

Do not break existing Slice 4 override UX.
If a manager already manually changed severity:
- preserve manager choice
- AI enrichment still writes ai_category / ai_explanation
- AI may store its suggested severity separately, but must not override manager choice

AI severity upgrade mapping:
- legal_language => at least High when clause meaning materially shifts
- financial_value => High
- date_deadline => High
- safety_threshold => High
- policy_change => Medium or High depending on wording
- meaning_change => Medium by default, High if major obligation/liability wording changed
- rewrite_equivalent => keep deterministic severity
- typo_correction => Low
- cosmetic_text => Low
- unclear => keep deterministic severity

Keep this logic deterministic in code after AI returns category.
