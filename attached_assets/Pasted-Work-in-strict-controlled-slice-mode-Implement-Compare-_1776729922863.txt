==================================================
A. UNION-RECT GROUP ZONES PER PANE
==================================================

Current state:
Slice 3 renders individual diff rects.

Replace that with grouped zones.

Rules:
- grouping is PER PANE, not global
- original pane groups are computed from rect_original
- revised pane groups are computed from rect_revised
- groups are linked by shared diff item IDs, not by raw pixel position

Algorithm:
- each diff item with a rect starts as its own rect on that pane
- any overlapping rects merge into a union rect
- repeat until no more overlaps remain
- group output:
  {
    id: stable group id,
    pane: "original" | "revised",
    rect: { x, y, w, h },
    itemIds: string[],
    highestSeverity: "high" | "medium" | "low",
    containsAdded: boolean,
    containsRemoved: boolean
  }

Important:
- If a diff item has null rect on a given pane, it does not create a group on that pane.
- Removed-only items may exist only on original.
- Added-only items may exist only on revised.
- A group with one item shows no count badge.
- A group with 2+ items shows a count badge in the top-right corner: "2", "3", etc.

Visual style:
- background color uses highest-severity color in that group
- border uses highest-severity border style
- if selected: solid violet 2px outer ring + brief pulse on first selection
- if hovered: fill brightens slightly + border intensifies
- keep overlays readable and non-destructive

Color mapping:
- High: rgba(239,68,68,0.18), red dashed border
- Medium: rgba(245,158,11,0.18), amber dashed border
- Low: rgba(107,114,128,0.12), gray dashed border
- Added-only group on revised: rgba(59,130,246,0.18), blue dashed border
- Removed-only group on original: red style
- On revised for removed-only items: show a small "REMOVED" badge at equivalent page position if already supported simply; otherwise defer that visual and do not fake it

Do not regress page rendering.
Do not change the existing fractional coordinate model.

B. SUMMARY ↔ PANE SELECTION SYNC
==================================================

Summary list items must now select diff items cleanly.

When a user clicks a summary item:
- selectedDiffId is set
- both panes jump to the matching pages
- the group containing that diff item becomes selected in both panes
- if a pane has no rect for that diff item, keep that pane on the linked page but do not force a fake group

When a user clicks a group zone in either pane:
- if the group contains exactly 1 item:
  - select that diff item
  - summary scrolls to and highlights it
- if the group contains 2+ items:
  - open a small mini-popover near the group listing the member diff items
  - clicking one member selects it and highlights it in summary

Mini-popover requirements:
- lightweight only
- no portal complexity unless already used elsewhere
- closes on outside click / Escape
- shows severity dot + short label per item

Summary selected row:
- stronger background
- left accent bar
- severity badge remains visible
- if item has severity override, show small pencil/edit indicator

==================================================
C. PANE ↔ PANE HOVER SYNC
==================================================

Hovering either pane must mirror to the other pane.

State model:
- hoveredGroupIdsOriginal: string[] or one selected original group id
- hoveredGroupIdsRevised: string[] or one selected revised group id
- cleaner option: hoveredItemIds: string[] derived from hovered group
Choose the cleanest approach.

Behavior:
- hovering a group in original pane highlights the linked group(s) in revised pane
- hovering a group in revised pane highlights the linked group(s) in original pane
- hovering a summary row highlights containing groups in both panes
- hover never changes selectedDiffId permanently
- hover is transient and clears on mouseleave

Use the existing PDF Editor mirrored-indicator interaction pattern as the reference style, but adapted for Compare Versions groups.
